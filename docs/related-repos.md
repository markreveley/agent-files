# Related repos — what agent-files takes from them

> Status: decision record · 2026-11-01 · companion to [ARCHITECTURE.md](../ARCHITECTURE.md) §6, §7, §9, §14
> Five of the operator's own repos were read (2026-11-01). Four arrived independently at the same core as agent-files — markdown with frontmatter, "agents propose, the human ratifies", views derived from source files. What is worth taking is the mechanisms each built around it.

## Adopted

| Mechanism | From | Where it now lives |
|---|---|---|
| Proposal schema with no `status` field; the runtime writes `proposed`. A node you write is accepted on write | socrates (`spec/loadout-v0.md`, `lib/socrates/gate.ex`) | ARCHITECTURE §7 |
| A gate before storage (cycles, dangling refs, undefined terms), errors back to the model for at most two repair rounds, rejected candidates archived | socrates | §7 |
| A proposal may depend only on nodes it was shown | socrates, itsjustshell2 (`tools/ask.exs` drops deps not on disk) | §7 |
| Supersession (`revises`) instead of editing accepted nodes | socrates (`amend`), elixir-mind (analysis only) | §7 |
| Reading-pace check: near-zero rejection or accepts within seconds means you stopped reading | socrates (plan 0006, "ratification fatigue") | §7 |
| Typed edges `supports` / `contradicts` / `refines`; `[[id]]` as mentions | artifact-dag (`SCHEMA.md`) | §7 |
| Lint rules as Datalog in a `.dl` file, with a small evaluator (~330 lines of JS there; to be ported to stdlib Python) | artifact-dag (`src/datalog.js`, `lint/rules.dl`) | §7 |
| A `fact` needs sources that resolve | elixir-mind (`lib/elixir_mind/verifier.ex`, `verified_by`) | §7 |
| No silent caps: say what assembly left out | itsjustshell2 ("4 of 8 shown") | §6 |
| Check the checks: mutate a valid input per rule, assert the right check fails | itsjustshell2 (`test/prop_checks.exs`) | §9.4 |
| Every standing rule names the check that arms it, or is listed as residue | itsjustshell2 (`docs/invariants.md` "Armed by:", `docs/methods.md` residue) | §9.7 |
| Build invalidation only after acceptance is shown to work | elixir-mind (documented, never built), socrates (built, never run on real input) | §14 (M5a / M5b) |

## Not adopted, and why

| Idea | From | Why not |
|---|---|---|
| Threads as transcripts written after the session | elixir-mind (`/capture`), manifold (`threads/`) | In agent-files the thread is the live record |
| Committed derived views, regenerated by CI | itsjustshell2, elixir-mind | Indexes are caches here (principle 7). If something derived is ever committed, check it in CI by regenerating and diffing, as both do |
| One-shot exchanges as the unit | itsjustshell2 | agent-files threads are multi-turn |
| artifact-dag as the KB itself | artifact-dag | No status lifecycle, retraction walk or grounding; Node rather than stdlib Python; its viewer runs only as a claude.ai artifact. Keep field names compatible where they overlap |
| Redacting archived message bodies | manifold | Conflicts with history never being rewritten |

## Worth remembering

- **manifold:** decisions linked to the turns where they were proposed and approved (`threads/README.md`) — the same link KB `decision` nodes should carry (`thread.md#t14`).
- **itsjustshell2:** a tripwires file — deferred decisions, each with the trigger that reopens it. m1-plan §6 is one.
- **itsjustshell2** has an apparent bug, found by reading (not run): `derive_threads.exs` `first_dep/1` keeps scanning into the body when frontmatter `deps:` is blank, which would explain why no `threads/` view is generated.
