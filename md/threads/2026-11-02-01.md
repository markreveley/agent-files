Keeping it extractable: the rule in detail

1. The format

  mixes the format with plans.
- Grow docs/examples/view-fixture/ into a conformance suite. A JavaScript viewer would be the third parser, after Python and Lua.
  "One parser" becomes "one spec, with fixtures enforcing parity".
- Implementation-only fields go in sidecars, never in the format.

2. The hook
- It is already standard-library-only and silent. Document its contract (event in, files out) so it installs and works alone,
  without the runner or Neovim.
- Add Codex the same way.

3. Links
- Make every turn addressable as <thread path>#tN. Turn ids are never renumbered, so the address is stable. Everything else points
  at it.
- Add commit trailers per §9.6 (Agent-Files-Thread, -Turn, -Decision).
- If an Entire-Checkpoint trailer is present, record its id in the thread's commits sidecar.
- Emit Agent Trace JSON only once that spec settles; its repo returned 404 today.
- Nodes cite turns and checkpoints in sources:. That is how the DAG attaches to the interactions.

4. The HTML viewer
- A static page built from the data root, like artifact-dag's build-viewer. It shows threads with their status, the DAG (reusing
  artifact-dag's viewer) and the provenance chain: decision → turns → commits.
- It is read-only. Editing in a browser comes only if a product follows, through a local server that obeys the same one-writer
  rules.
- It tests the GUI weakness, and gives you something you can share.

Making approval optional

- The gate is mandatory. It is a machine check: no cycles, no dangling references, sources resolve.
- Acceptance is a policy per node type: manual, auto, or sample N%. For example, decisions manual and facts automatic once their
  sources resolve.
- Each node records who or what accepted it: accepted_by: <name> or rule:<policy>.
  - Attribution survives automation, which keeps your main strength intact.
  - Grounding can require a human-accepted node where it matters.
  - Invalidation works the same either way.
